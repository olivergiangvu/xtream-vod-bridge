# Xtream v0.6 Unified Stable — gated HomeDocker release checklist

Status: offline implementation on PR #44. This file does not authorize any server change.

## Non-negotiable release architecture

- One production Docker container, one Uvicorn worker, one ASGI lifespan, one Playback/Admin listener.
- Maximum one **temporary** unified Canary container during development; retire it after acceptance.
- Retain public HTTPS listener :18450, existing manifest/stream URLs and RBAC/session/gateway security.
- Preserve source secrets/data, no shared production DB writes from Canary.
- Do not stop or throttle Homebridge, Netdata, AIOStreams, CrossWatch, Portainer or unrelated workloads.

## M1 — Resource isolation and Canary retirement

Original live inventory: four Xtream containers, 214.24 MiB Docker memory snapshot;
the two legacy Canary containers used 99.63 MiB, Canary Playback showed 30.70%
of one core in one instantaneous sample, host PSI avg10 67.21%. These are **not**
steady-state load claims. User authorized controlled STOP of only
xtream-vod-canary-admin and xtream-vod-canary-playback.
Do not proceed until HomeDocker confirms CANARY_BOTH_STOPPED=PASS and production
container IDs/images/health remain unchanged. Keep image, Compose and data.
After stopping, measure 5–15 minutes of comparable traffic and host PSI/CPU/RSS.

## M2 — Single-process offline implementation

- unified_app.py combines bridge routes and mounted Admin sub-app, with explicit combined lifespan.
- A new /live endpoint has no SQL, remote network or catalog scans; /ready does SELECT 1.
- Keep existing rich /health compatible, but never use it for periodic Docker healthchecks.
- admin_ui.py uses localhost playback URL only when XTREAM_UNIFIED_MODE=1.
- Dockerfile.unified is the source-based stable artifact.
- canary/Dockerfile.unified-offline inherits an existing verified local candidate and only COPYs reviewed files.
- canary/unified-compose.yaml runs exactly one temporary container, without published ports;
  disables legacy provider scheduler, uses 60s /live healthcheck and internal Docker network.
- Security requirement: review public nginx prefix stripping and ensure internal gate-check is never public.

## M3 — Immutable image and one-container Canary

1. Run SHA-pinned stage6_unified_image_build.py in --plan mode only after M1 STOP.
2. Separate approval for exact-tag --build: no Docker run/recreate, no image pulls, no build RUN;
   resource gate CPU utilization <75%, PSI samples <70%, RAM available >=1 GiB, Docker disk >=2 GiB.
3. Independently review a one-container Canary launch script with no ports and exact Compose diff.
4. Validate direct Docker internal /live, Admin gateway, cookie paths, role controls, /a/ and /play/.
5. When done, stop the temporary Canary instead of leaving it always on.

## M4 — Stable acceptance

- Functional: Safari gateway, login and CSRF, User/Admin RBAC, manifest, movie/series streams, playback signatures.
- Resource: 5–15 minute CPU/RSS/PSI baseline comparing matching request loads.
- Process: one Uvicorn process and one scheduler, no extra Admin background timers.
- Isolation: zero published Canary ports, internal network only and own secrets/data.
- Security: no public /api/auth/gate-check; cookie Path and same-origin checks preserved.
- Compatibility: existing /health status and public manifest/relay URL formats unchanged.
- Reliability: stop/restart test in Canary only, healthcheck recovery, verifiable rollback.

## M5 — Production staged cutover: requires **separate explicit approval**

1. Build reproducible unified image from pinned release commit.
2. Launch one production candidate on a collision-checked 127.0.0.1-only spare host port;
   never bind the occupied 18767 or 18768 while legacy containers still run.
3. Smoke-test all paths via loopback without touching the live :18450 ingress.
4. Backup exact production Compose and nginx. Review every nginx proxy route so
   /a/, /play/, /admin/, /admin-signin/ and the internal auth gate share one backend.
5. Atomic nginx config change only after approval, nginx -t, reload, verify security and playback.
6. If anything fails, restore nginx backup and confirm original two production IDs/health.
7. Only after observation, retire legacy production Admin and Playback by exact IDs.
   Preserve shared data and rollback images; avoid docker system prune / volume prune.
8. Stop/remove the temporary unified Canary. Target: exactly one running Xtream container.

## Release STOP conditions

Unexpected SHA/config drift; wrong network, published Canary port, unhealthy production;
CPU pressure beyond gate, unknown rollback state, nginx error or unverified login/stream.
Never reduce safety thresholds simply to force deployment.
