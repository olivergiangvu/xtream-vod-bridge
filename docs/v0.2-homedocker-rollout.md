# Controlled HomeDocker v0.2 rollout (do not deploy from CI)

## Preconditions

- GitHub CI + CodeQL pass and the PR is reviewed/merged.
- Confirm existing Xtream v0.1.3 container is healthy and Range/206 playback passes.
- `nginx` HTTPS :18450, localhost Docker :18767, `PUBLIC_BASE_URL` and three separate secrets are unchanged.
- Use authorized provider content and consider the security implications of opt-in cleartext provider→CDN HTTP.

## 1. Consistent backup before upgrading (SSH only)

```bash
cd /opt/xtream-vod-bridge || exit 1
STAMP=$(date +%Y%m%d-%H%M%S)
SAFE_DIR="/root/xtream-vod-pre-v02-$STAMP"
sudo install -d -m 700 "$SAFE_DIR"
sudo cp -p .env "$SAFE_DIR/env.bak"
sudo cp -p compose.yaml "$SAFE_DIR/compose.yaml.bak"
sudo docker exec xtream-vod-bridge python -c "import sqlite3; a=sqlite3.connect('/data/index.sqlite'); b=sqlite3.connect('/data/index.pre-v02.sqlite'); a.backup(b); b.close(); a.close()"
sudo docker cp xtream-vod-bridge:/data/index.pre-v02.sqlite "$SAFE_DIR/index.sqlite"
sudo chmod -R go-rwx "$SAFE_DIR"
echo "Pre-upgrade config and consistent SQLite snapshot saved outside container"
```

The snapshot contains copyrighted media *index metadata*, not provider credentials (secrets are stored separately in `env.bak`). Keep both private and under the existing encrypted Backrest/restic DR policy. Later remove the redundant copy within the named volume only after confirming the external copy.

## 2. Checkout approved SHA and stage configuration

```bash
cd /opt/xtream-vod-bridge
sudo git status --short
sudo git fetch -q origin main
# Use an explicit approved commit SHA rather than live moving 'main'
sudo git checkout --detach <REVIEWED_MERGE_SHA>
sudo nano .env
```

Change only the two existing values after reviewing provider terms:

```dotenv
MOVIES_ONLY=0
XTREAM_HTTP_REDIRECT_MODE=public-ip
XTREAM_HTTP_REDIRECT_ALLOWED_IPS=
```

Keep `PUBLIC_BASE_URL`, `XTREAM_BASE_URL`, credentials and HMAC secrets unchanged. The dynamic policy refuses private/loopback/reserved/multicast addresses, hostname-based HTTP downgrade and non-default ports, **but it trusts all public IPv4 destinations on port 80**. If unacceptable, leave `allowlist` mode and use a provider HTTPS CDN or the previous fixed-IP list instead. The `.env` file must remain root-only (mode 0600).

## 3. Upgrade only the bridge

```bash
sudo docker compose config --quiet
sudo docker compose up -d --build --no-deps xtream-vod-bridge
sudo docker compose ps
sudo python3 scripts/probe_playback.py --samples 3
sudo python3 scripts/smoke_test.py
curl -fsS http://127.0.0.1:18767/health
```

The probe now waits briefly after recreate and validates query-free named URL signatures and small Range/206 responses. Zero disruption is not guaranteed for in-flight video sessions: schedule during low activity.

## 4. Series & anime tests

Initial `series.total` and `episodes` are likely incomplete until the first `get_series` / `get_series_info` sync and enrichment finish. `MAX_ENRICH_PER_SYNC` is shared with movies and throttles provider requests; **do not blindly set thousands**. Validate one real IMDb/TMDb series episode and one season 0 special where present. If the provider supplies AniList/Kitsu/MAL IDs, test exact tagged lookups; otherwise no result is expected for those ID types. Do not fabricate anime ID matches from titles.

Within AIOStreams, request a movie and a TV episode, then verify:
1. The existing Xtream addon appears with human-readable filename and correct SxxExx label.
2. Other addon sources retain their original fallback order.
3. mpv's filename is `Title.Year.mkv` or `Show.S01E02.mkv`, without query `?exp=&sig=`.
4. Seeking, playback completion and downstream Trakt history are actually tested. *Readable file paths alone cannot guarantee Episode Info+ or other trackers parse exact IDs; a consumer may need to parse the signed `/tt...` or `/tmdb-...` path segment.*

## 5. Rollback without losing the index

```bash
cd /opt/xtream-vod-bridge
sudo git checkout --detach d79ab7181be6a0e073d08011bd1b4b902fb2138d
sudo docker compose up -d --build --no-deps xtream-vod-bridge
sudo docker compose ps
```

Old application code ignores the additional nullable anime columns; named v0.2 URLs already issued won't work on v0.1.3, but legacy query URLs are unchanged. For strict configuration rollback restore the private `env.bak` and recreate only this container. **Never use `docker compose down -v`**.

## Remaining limitations

- No automatic AniList/Kitsu ↔ IMDb/TMDb cross-provider mapping. Requires a tested ID crosswalk, likely involving AIOMetadata.
- No HLS manifest/segment rewriting, transcoding, real codec/resolution detection or multi-provider support.
- Provider→CDN cleartext HTTP risk remains in dynamic mode.
- Existing third-party mpv/Jellyfin tracking plugins may need separate updates to read the signed content ID path.
