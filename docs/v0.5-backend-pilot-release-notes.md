# v0.5 Backend Pilot — Developer Release Notes

**State:** Experimental, PR #39 + PR #40. This is NOT yet the HomeDocker production release. Current production stable: separate \`xtream-vod-admin:0.4.3-manifest\` and existing playback container. Do not run \`docker compose up\` from GitHub main, and never use \`docker compose down -v\`.

## Scope shipped in PR39 / PR40

- Exactly two effective roles: \`admin\` for existing \`owner\`, and \`user\` for personal accounts.
- New User accounts have their own password and HttpOnly cookie session; Admin can disable/reset them and revoke all of their sessions, including nginx \`auth_request\` gate.
- User-created source configurations are owner-scoped and encrypted via \`SOURCE_SECRETS_KEY\`, a separately generated persistent Fernet key. This must be part of secure disaster-recovery backups.
- Source configuration types: \`xtream\` (HTTPS base URL, provider username, password), \`m3u\` (remote HTTPS playlist URL). Source test and bounded manual sync are per-user. Provider/playlist URLs may contain secrets; they are not returned by the API.
- Manual sync stores provider-specific VOD items and episodes in separate tables \`tenant_media\`/\`tenant_episodes\`. Only explicit IMDb/TMDb IDs are matched: no unverified fuzzy mapping or Live/EPG.
- Create 1–8 personal manifests per user, choose owned sources, rotate/revoke. URL is shown ONLY on issuance/rotation, token is hashed in DB. \`GET /api/my/manifests\` never returns raw URLs.
- AIOStreams consumes personal \`/a/v5_<secret>/manifest.json\` and \`/a/v5_<secret>/stream/{movie|series}/{id}.json\` without browser cookies.
- Personal playback is HMAC-v5 signed, scoped to manifest/source/media and revalidates owner-enabled/source-enabled/manifest membership on every request. Existing global manifest and old signed Movie/Series relay remain unchanged.
- New HTTPS Range 206 / HEAD relay is tested with a fake upstream. No production CDN testing performed yet.

## API map (under nginx /admin/api/ proxy)

| Endpoint | Allowed |
|---|---|
| \`GET /api/auth/session\` | Browser with optional authenticated session; reveals own role only |
| \`GET /api/my/overview\` | Admin and User; own source list |
| \`GET/POST /api/my/sources\` | Admin and User; own only |
| \`PATCH/DELETE /api/my/sources/{source_id}\` | Owner of that source only |
| \`POST /api/my/sources/{source_id}/test\` | Source owner; safe public HTTPS probe |
| \`POST /api/my/sources/{source_id}/sync\` | Source owner; bounded, cooldown |
| \`GET/POST /api/my/manifests\` | Admin and User; own only |
| \`PATCH/DELETE /api/my/manifests/{manifest_id}\` | Manifest owner |
| \`POST /api/my/manifests/{manifest_id}/rotate\` | Manifest owner |
| \`GET/POST/PATCH/DELETE /api/system/users\` | Admin only |
| \`GET /api/overview, /api/events, /api/manifest\` | Admin only (legacy) |
| \`PUT /api/settings\` | Admin only (global) |
| \`GET /a/{token}/manifest.json\` | Legacy token or valid personal token |
| \`GET /a/{token}/stream/{type}/{id}.json\` | Legacy or personal scoped content |
| \`GET/HEAD /play/v5/...\` | Signed path + active scoped rights |

## Production compatibility and restrictions

1. **Do not deploy the development PR yet.** It changes both Admin and Playback binary. The legacy \`0.4.3-manifest\` Admin image is the rollback reference. For production, plan a staged test using copied SQLite database, copied .env with secret substitutions, different Docker service names, **different loopback ports**, and isolated Docker volumes.
2. This stage has no native frontend for User source creation. The existing Admin UI still shows the global controls and should not be exposed as the User-facing screen. Frontend v0.5D must detect \`role=user\` and render My Sources / My Manifests instead of the Admin dashboard.
3. **No automatic background sync** of personal sources yet. Manual sync quota caps Xtream detail requests (12 movie and 20 series details per source, each sync not more often than 5 minutes). Some provider titles may not have usable IMDb/TMDb IDs, so actual coverage may be incomplete.
4. **HTTPS only for user-configured source URLs and stream files.** Many Xtream providers only offer plain HTTP or redirect to rotating HTTP CDNs. They must not be silently accepted. Add separately reviewed Admin allowlist policy and test DNS pinning/cert verification before enabling cleartext HTTP.
5. **M3U VOD with explicit IMDb/TMDb only.** M3U Live/EPG ignored; HLS \`.m3u8\` segment URL rewriting is not implemented and must be tested before advertising support. Some M3U query/header auth modes are unsupported.
6. IP pinning and no-follow-redirects protect against user-controlled SSRF. Resolve and check addresses at actual connection time; no unsafe IP/host rewrites. Certificate validation must remain enabled even with IP-pinned TCP.
7. **The Fernet encryption key is a disaster-recovery dependency.** Losing it makes users' encrypted credentials inaccessible. Never put it in Git, UI, logs or screenshots. Rotate only with an explicit re-encryption procedure.
8. Keep old nginx \`/a/\` and \`/play/\` routes. Both v5 routes live beneath those prefixes; do not add public \`18768\` mappings.

## Suggested canary acceptance (before production)

- Create a consistent SQLite snapshot using the SQLite Online Backup API; save Compose, nginx config, .env securely and both active image IDs. **Do not copy an active WAL SQLite file as a standalone file.**
- Run isolated v0.5 Admin and v0.5 Playback with different names/ports, a copied DB and a separate test source.
- Verify existing owner cookie/session migrates, existing Xtream manifest stream and Range 206 still work.
- Create test User; save Xtream source or M3U URL; test source; sync; generate personal manifest; verify AIOStreams Custom Addon displays a known Movie and Series matched by true IMDb/TMDb IDs.
- Confirm cross-user source and manifest accesses all return 403/404, including guessed source IDs and disabled accounts. Revoke manifest and immediately deny new addon and playback requests even with a previously signed URL.
- Verify real upstream Range \`bytes=0-1\` returns 206, HEAD works, Safari Login/Lock/Autofill/Refresh unchanged, and sensitive URLs do not appear in logs.
- Promote only after canary and negative tests; rollback requires restoring **both** compatible old images and the prior Compose plus tested snapshot when necessary.
