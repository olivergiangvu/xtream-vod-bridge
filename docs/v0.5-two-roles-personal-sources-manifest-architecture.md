# v0.5 — Hai vai trò (Admin / User), nguồn Xtream hoặc M3U, manifest cá nhân

**Trạng thái:** Design / Architecture Decision Candidate — CHƯA triển khai.  
**Production baseline:** HomeDocker Admin `0.4.3-manifest`; playback container vẫn đang chạy độc lập.  
**Đầu vào:** phản hồi người dùng 13/10/2026: không dùng Owner/Admin/Viewer; muốn mô hình tương tự AIOStreams, User tự tạo manifest riêng, không sửa được advanced addon settings; và phải có giao diện cấu hình Xtream login hoặc M3U playlist.

## 1. Quyết định sản phẩm

**Chỉ có đúng hai role:**
- **Admin**: toàn quyền cài đặt hệ thống, user management, provider policies, security, advanced bridge settings, monitoring. Admin cũng là một User về mặt sở hữu nguồn & tạo personal manifest.
- **User**: đăng nhập Username + Password, quản lý **nguồn riêng của mình** (Xtream Codes hoặc M3U), kiểm tra kết nối, cấu hình personal addon cơ bản (source alias, lựa chọn nguồn, movie/series enable), tự tạo/rotate/revoke manifest URL. Không chỉnh global advanced settings, không xem nguồn/manifest của người khác, không quản trị user.
- `owner` đang chạy được **migrate thành Admin đầu tiên**, giữ nguyên mật khẩu, không thêm role `owner`. Không thay đổi login Gateway hiện tại.
- **Không có Viewer, không có lớp quyền thứ ba**.

### Quyền cần enforce tại backend (không chỉ ẩn UI)

| Tác vụ | Admin | User |
|---|---:|---:|
| Login / Dashboard cá nhân | ✓ | ✓ |
| Thêm/sửa/xóa nguồn Xtream/M3U **của chính mình** | ✓ | ✓ |
| Test nguồn, xem status sync/index cá nhân | ✓ | ✓ |
| Tạo nhiều personal manifests, chọn nguồn, đổi tên, rotate/revoke | ✓ | ✓ |
| Lấy/Copy manifest của chính mình | ✓ | ✓ |
| Xem/đọc manifest, user credentials của người khác | Theo chính sách admin; **mặc định không đọc plaintext** | ✗ |
| Global JIT, sync quota, metadata, redirect/CDN policy, proxy, security | ✓ | ✗ |
| Tạo/disable/reset tài khoản User | ✓ | ✗ |
| Quản lý toàn hệ thống, troubleshooting, backup | ✓ | ✗ |

**Hai trục khác nhau:** Role (`admin` / `user`) không phải Provider Type (`xtream` / `m3u`); cũng không phải Manifest. Một user có thể có 0..N sources và 0..N personal manifests.

## 2. UX — phân cấp theo AIOStreams

**Public Gateway (giữ nguyên):** `/admin-signin/` ở HTTPS :18450 có Username + Password, Safari Passwords/autofill, nonce, CSRF, session, Lock → Gateway. Tên route có thể được đổi trong major version sau; **không đổi khi migrate**.

**Sau login:**
- **User homepage:** `My Sources` → `Add Source` → `Test Connection` → `Sync Status` → `My Addon / Create Manifest` → Copy / Show / Rotate / Revoke. Không có mục advanced server settings.
- **Admin homepage:** có cùng `My Sources` / `My Manifest`, cộng thêm `System` (Global Settings, Health/JIT/Diagnostics, User Management, Security Policy).
- Giữ preview Source label (Strand-like), rõ `Movie`/`Series`; tuyệt đối không hiển thị Xtream password, M3U secret query-string, cookie hoặc raw URL trong sự kiện/log.
- Cả hai role được phép có **tên hiển thị**, lựa chọn sources và các thiết lập addon đơn giản, nhưng các giới hạn sync/redirect, metadata trust, per-user quotas thuộc Admin.

## 3. Nguồn cấp dữ liệu (User-owned)

### 3A. Xtream Codes

Form: `Source name`, `Server URL`, `Username`, `Password` (masked), `Test Connection`, `Enable movies`, `Enable series`.

- Gọi Xtream `player_api.php` với credentials ở server; không lộ trong manifest/browser stream response; test `user_info.auth` + thông tin truy cập cần thiết; hiển thị trạng thái nhưng không trả server secret.
- Mặc định HTTPS. HTTP-only Xtream providers chỉ được dùng qua **Admin-approved provider policy**, và phải có cảnh báo cleartext credentials.
- Xtream global hiện có từ `.env` phải được giữ như **legacy source của Admin**; không ép di chuyển credentials trước khi chức năng mới qua nghiệm thu.
- Không chèn provider password vào URL trong các phần tử DOM, browser-local storage hoặc logs.

### 3B. M3U playlist

Form: `Source name`, `Playlist URL` (bao gồm URL token nếu provider yêu cầu, masked), hoặc **upload file .m3u/.m3u8** tùy policy triển khai; `Test / Preview`, `Sync`; movie/series enable.

- Parse có giới hạn bytes/entries/line length, chuẩn `#EXTM3U`, `#EXTINF`, các attributes như `tvg-id`, `group-title`, label, resolution, video stream URL; tự nhận dạng `#EXTVLCOPT`/ `#KODIPROP` nhưng không tự động gửi HTTP headers/cookies ngoài allowlist.
- M3U có thể bao gồm Live TV. **Phase v0.5 chỉ hỗ trợ VOD Movie/Series**: Live TV/EPG không phải phần tự động của release này. Một entry không xác minh được IMDb/TMDb và/hoặc SxxEyy thì không được fuzzy-match ra nội dung khác.
- Metadata ID mapping: ưu tiên explicit IMDb/TMDb ID (hoặc metadata được kiểm chứng); không coi `tvg-id` của kênh live là IMDb/TMDb. Optional lookup phải có độ tin cậy rõ ràng và cơ chế review.
- Playlist URL & dòng stream có thể chứa credentials; xử lý như secret, không echo/log/cache HTML.

### 3C. SSRF & network egress (bắt buộc)

User tự nhập URL nên rủi ro SSRF lớn hơn nguồn Xtream hiện trong `.env`:
- Chỉ cho `https` theo default; không chấp nhận `file:`, `ftp:`, `data:`, `javascript:`, private/loopback/link-local/reserved/multicast IP, cloud metadata IP, Unix sockets, userinfo URL. Cấm hostname trỏ vào mạng nội bộ kể cả redirect/rebind DNS.
- Kiểm tra IP thật **khi connect** (IP pinning hoặc transport resolver kiểm soát), không chỉ check DNS một lần. Validate từng redirect; chặn internal Docker hosts, `127.0.0.1:18768`, nginx admin nội bộ, NAS và Docker socket.
- Hạn chế ports, timeout, response bytes, stream length, refresh rate, số sources/user; chống zip bomb, XML entity, parser DoS (nếu thêm hỗ trợ format).
- Nếu có nguồn LAN được phép, chỉ **Admin** tạo explicit narrowly-scoped host:port egress allowlist — User không tự bỏ restriction.
- Không tái sử dụng `safe_redirect()` dựa trên global `BASE`; phải ràng buộc redirect policy theo source.

## 4. Data model & multi-tenancy

Các bảng mới (tên đề xuất; migration có version, đảm bảo idempotent):
- `auth_users(user_id,username,role,enabled,salt,digest,rounds,created_at,updated_at)` — owner legacy chuyển thành user `admin` đầu tiên, không lưu plaintext.
- `auth_sessions(...,user_id,...)` hoặc additive `user_id` trên sessions cũ.
- `sources(source_id,owner_user_id,type,display_name,enabled,sync_status,updated_at)`.
- `source_secrets(source_id, encrypted_payload,nonce,key_version)` — encrypted-at-rest; key encryption nằm ngoài DB, trong secret file/.env quyền hạn chế, có rotation; nghiêm cấm trả plaintext qua API.
- `provider_items(source_id,kind,source_item_key,...IMDb/TMDb...)`, `provider_episodes(source_id,series_key,season,episode,stream_key,...)` — khóa tổng hợp gồm `source_id`; tránh Xtream `stream_id` trùng giữa các provider.
- `personal_manifests(manifest_id,owner_user_id,token_hash,display_name,enabled,created_at,rotated_at)`, `manifest_sources(manifest_id,source_id)` with ownership checked transactionally.
- `crosswalk` global IMDb↔TMDb mapping có thể cache chung **chỉ khi không chứa provider-private information**.

Không thêm `source_id` vào primary key `items`/`episodes` hiện tại bằng destructive migration ngay. Dùng bảng provider mới song song; migrate nguồn hiện tại theo từng bước và giữ legacy playback/index hoạt động.

## 5. Manifest + playback isolation (khác biệt quan trọng)

Hiện tại `/a/{ADDON_TOKEN}/...` kiểm tra **một** token global, `items` + `episodes` không có `source_id`, và `/play` HMAC chỉ ký kind/stream ID/media ID/expiry/filename. Không thể chỉ phát thêm token UI vì stream của User A có thể trỏ dữ liệu nguồn User B.

**Target behavior:**
1. User đăng nhập vào web UI → tạo ít nhất một personal manifest chọn các nguồn **do chính mình sở hữu**.
2. Backend phát sinh token ngẫu nhiên mạnh, lưu hash (không lưu raw token); chỉ cho xem một lần / hành vi reissue rõ ràng.
3. AIOStreams/Stremio gọi `/a/{personal-token}/manifest.json` và `/a/{personal-token}/stream/...json` **không có browser cookie**; bridge lookup token hash + manifest owner + enabled + selected source IDs.
4. Stream resolver tìm `provider_items` / `provider_episodes` **chỉ trong các nguồn được gán**; `source_id` có mặt trong mọi lookup, JIT, cache keys, cooldown/lock names; không rò rỉ source khác.
5. HMAC playback **v3** ký `manifest/user scope + source_id + kind + stream_key + media identity + expiry + filename`; relay kiểm tra tồn tại, quyền, secret của nguồn và policy theo nguồn trước khi thực hiện Range/206. Không gửi provider credentials cho client.
6. Rotate/revoke Manifest token → route `/a` ngừng hợp lệ ngay. Với playback URL đã phát trước đó cần chính sách rõ ràng: **ưu tiên kiểm tra manifest enabled và source ownership lại ở relay để revoke lập tức**, đồng thời vẫn giữ `Range/206`, HEAD, resume. Có thể cân nhắc grace window ngắn theo policy nếu cần.
7. **Legacy:** giữ `/a/{legacy-token}` và `/play` v2 đang chạy đến khi người dùng chuyển sang manifest cá nhân, không xóa index/volume/token cũ.

## 6. Authorization/API contract (draft)

Browser API (nginx same HTTPS):
- `GET /api/auth/session`: `username`, role `admin|user`.
- `GET/POST /api/sources`, `PATCH/DELETE /api/sources/{id}`, `POST /api/sources/{id}/test`: ownership or admin policy; never return secret.
- `GET/POST /api/my-manifests`, `PATCH /api/my-manifests/{id}`, `POST .../{id}/rotate`, `DELETE .../{id}`: own only.
- `GET/PUT /api/system/settings`, `GET/POST/PATCH/DELETE /api/system/users`: Admin only.
- `GET /api/overview`: user receives metrics for own sources; admin sees global overview.
- **Existing `GET /api/manifest`** remains an Admin legacy manifest URL until superseded; do not silently reinterpret it as per-user.
- CSRF/origin enforcement on all mutations; no Bearer token in URL, browser localStorage or JS bundle.

## 7. Release stages & compatibility gates

1. **Freeze v0.4.3:** backup host Compose, `.env`, nginx, source and image digest + consistent SQLite Online Backup API snapshot; no `docker compose down -v`.
2. **v0.5-A auth:** migrate only two roles `admin/user`, keep `owner` username as Admin, cookie/session compatibility. Test revoked/disabled users across nginx gateway and APIs.
3. **v0.5-B sources:** add Xtream/M3U server-side source connectors, vault, per-user ownership, SSRF egress guard; test with mock Xtream/M3U and no real production credentials.
4. **v0.5-C manifests + playback:** provider-scoped index, personal manifest URL/token, source-aware JIT, signed playback v3. **Requires new playback image**; cannot be accomplished by updating only Admin frontend/container.
5. **v0.5-D UI:** User Sources, Test, sync progress, Create Manifest, Show/Copy/Rotate, and Admin-only Advanced settings/Users panels. Integration must preserve Safari native POST login, Lock redirect and Refresh status.
6. **Canary:** enable one test User, one Xtream source and one M3U sample; confirm cross-user isolation, missing-ID nonmatch, SSRF blocks, manifest revoke, Movie/Series HTTP Range 206, AIOStreams Custom Addon, Remux/Trellis playback. Only then migrate legacy Admin source in-place, with simple image/SQLite rollback.
7. **No broad API exposure:** keep backend `127.0.0.1:18768` and existing nginx 18450 routing; do not turn the Admin port public.

## 8. Explicit exclusions and choices requiring product confirmation

- User accounts must not be confused with Xtream provider usernames.
- Live TV/EPG and general-purpose M3U channel catalog support are **out of v0.5 VOD scope** unless separately approved.
- Default: sources are **private to the user who adds them**. Optional `Admin-managed shared source` is postponed pending a privacy model; no implicit cross-user sharing.
- Users can have **multiple** personal manifests, each selecting one or more of their sources.
- Username `owner` remains as the original Admin login; role value is `admin`.
- Uploading .m3u from browser is optional second delivery mode; remote Playlist URL first, unless specifically requested.

## 9. Acceptance criteria (blocking)

- Role list exactly `admin` + `user`; `viewer` and `owner` are not role values.
- User can enter Xtream base URL + credentials **or** M3U URL/file and test without secret disclosure.
- User can generate, copy, revoke a scoped manifest accepted by AIOStreams; not change any global advanced setting.
- User A cannot see/use User B sources, manifests, index, JIT cache, signed playback, or credentials, even guessing IDs/tokens.
- Missing/expired/revoked manifest returns 404/401 in safe form; errors and logs never contain source URL/query secrets.
- Existing v0.4.3 global manifest and signed Movie/Series playback continue functioning during migration.
- Rollback path tested on a **consistent SQLite snapshot**, not file copy of live WAL DB.
- Safari Passwords autofill, Lock→Gateway, Refresh Status, HTTPS `same-origin` preserved on HomeDocker.
